  v0.5.8   2026-11-02    字体在 GitHub Pages 上退回默认：路径多写了一层「..」
================================================================================
【一句话】
  部署到 GitHub Pages 以后，页面上的字变成了系统默认字体。原因是样式表里
  引用字体的路径多退了一层目录 —— 在本机（网站根目录）碰巧还能找到，
  放到 GitHub Pages 的 /仓库名/ 子目录下，就退到网站根目录外面去了。
  把路径改回正确的一层就好。


--------------------------------------------------------------------------------
【改动】
--------------------------------------------------------------------------------
  · 字体路径少退一层  ——  assets/app.css

    原来是 url("../../fonts/SmileySans-Oblique.ttf.woff2")。样式表自己就在
    assets/ 里，往上一级就是项目根目录，一层「..」刚好；写两层会退到根的
    外面。本机预览时网址是 http://localhost:5173/assets/app.css，再往上退
    已经没有地方了，浏览器就地停在根目录，于是碰巧还能找到 fonts/；
    到了 GitHub Pages 的 https://…github.io/仓库名/assets/app.css，
    两层「..」就退到了 https://…github.io/，字体自然 404，只能退回默认字体。

    改成 url("../fonts/SmileySans-Oblique.ttf.woff2")。

  · 自检里多一条：字体路径必须落在 fonts/ 里  ——  scripts/smoke.mjs

    按样式表所在目录解析一遍路径，文件不存在就报 FAIL，免得下次又写错层数。

  · 离线缓存版本从 v15 升到 v16  ——  sw.js


--------------------------------------------------------------------------------
【升级须知】
--------------------------------------------------------------------------------
  1. 已经装到主屏的，打开一次新页面就会自动换成新版；字体本身没换，
     只是路径改对了。
  2. 本机预览看起来不会有变化（以前碰巧也能加载到）。


--------------------------------------------------------------------------------
【怎么验证】
--------------------------------------------------------------------------------
  1. 打开 GitHub Pages 的网址，字应该变成带点倾斜的「微笑黑体」，不再是
     系统默认的圆体 / 黑体。
  2. 打开浏览器的开发者工具 → 网络（Network）→ 刷新，找
     SmileySans-Oblique.ttf.woff2，状态应该是 200，不是 404。
  3. 自动自检：

         node scripts/smoke.mjs

     应该看到「字体路径从 css 所在目录算，正好落在 fonts/ 里」，最后一行
     「全部通过」。

  v0.5.6   2026-10-11    弦音能中途喊停了；生成中退出界面再回来，三个点还在
================================================================================
【一句话】
  三件事。一、弦音终于能中途喊停 —— AI 回话时那个方形的停止键一直都在，
  但点了从来不管用。二、AI 正在往外吐字的时候，你要是不小心退出了弦音界面
  再回来，那三个跳动的点、「停止」键全都不见了，AI 后面吐的字还会丢；
  现在退出去再回来，正在生成的样子原样都在。三、加服药日程时填单位那个框，
  样式跟旁边别的输入框统一了，不再是浏览器默认那个方角框。


--------------------------------------------------------------------------------
【改动】
--------------------------------------------------------------------------------
  · 「停止」真能停了  ——  assets/js/modules/assistant.js

    按钮一直都在（AI 回话的时候，发送键那个位置会换成方形的停止键），
    但它的点击从来没接上线：管点击的那段代码只认带 data-chord 记号的按钮，
    这个键上没带，所以点了等于没点，只能干等 AI 说完。

    现在接上了：点一下，这一轮立刻停下，已经吐出来的话留在气泡里，
    下面注明「（停在这里了）」，接着就能打字问下一句。
    喊停之后它也不会再自作主张接着去读你的记录。

  · 生成中退出界面再回来，三个点还在（吐出来的话也不丢）

    毛病出在「回到这一页」这个动作上：每次回到弦音页，页面都会从本机存的那份
    聊天记录重新铺一遍；而在生成中的那条 AI 回话还没存（要等它说完才存），
    于是被抹掉了 —— 三个点的小框没了、「停止」没了，AI 后面吐的字写进了一个
    已经不在屏幕上的气泡里，最后连这条回话本身都存不进去，等于白说。

    现在正在生成的那条会被记在手上：只要它还没结束，回到这一页就不重新铺，
    而是把屏幕上那个气泡重新认一遍，字接着往里写。等它说完（或者你喊停），
    照旧存下来；下次进来从本机读，是一条完整的记录。

  · 剂量单位的框，样式统一  ——  assets/js/modules/calendar.js + assets/app.css

    上一版把候选改成一排按钮之后，右边那个填单位的框还是浏览器默认模样：
    方角、灰边框，跟上下别的框（开始日期、药物名称、时间）不是一个样子。
    现在套上全站统一的输入框样式：圆角、半透明白底、一样的边框。

  · 离线缓存版本从 v13 升到 v14  ——  sw.js


--------------------------------------------------------------------------------
【升级须知】
--------------------------------------------------------------------------------
  1. 以前记的日程、聊过的内容，一条都没动。
  2. 「停止」只停当前这一轮，不关掉弦音，也不影响已经记下的日程。
  3. 生成中退出界面，AI 其实还在说 —— 它没被打断，只是你不在看。
     回到弦音页就能看到它说到哪儿了。


--------------------------------------------------------------------------------
【怎么验证】
--------------------------------------------------------------------------------
  1. 弦音里发一句需要想一会儿的话（比如「帮我把这周的睡眠捋一遍」）。
     话发出去、还没出字的时候，右下角发送键那个位置是个方形的停止键。
     点它，这一轮立刻停下，气泡下面写「（停在这里了）」，接着就能打字。
  2. 再发一句，等三个点冒出来之后，按左上角返回、回主页，再进「弦音」。
     三个点应该还在跳，「停止」还在，AI 接下来吐的字应该接在屏幕上那个气泡里。
  3. 自动自检（可选，装了 Node 就行）：

         node scripts/smoke.mjs

     浏览器开 http://localhost:5173/scripts/flowcheck.html 和
     http://localhost:5173/scripts/modcheck.html ，
     右边那栏最后一行应该都是 DONE，并且一个 FAIL 都没有。

  v0.5.5   2026-10-11    修手机上的 bug：安卓点剂量单位弹不出候选，改成一排按钮
================================================================================
【一句话】
  修一个只在手机上才犯的毛病。加「服药」日程时，「每次剂量」右边那个填单位的框
  在电脑和 iPhone 上都正常，可在安卓手机（Chrome / Edge / 三星浏览器）上点了
  只会弹键盘，一个候选都不出 —— 因为那个框用的是 <datalist>，而安卓上的这几个
  浏览器从来没支持过它。这一版把候选清单换成一排按钮，点一下就填进去，手机上
  妥妥的；同时那个框还在，想填「半片」「2.5ml」这种照样能自己打。


--------------------------------------------------------------------------------
【改动】
--------------------------------------------------------------------------------
  · 「每次剂量」的单位，从候选清单改成一排按钮  ——  assets/js/modules/calendar.js

    原来那个框是 <input list="calUnits"> 配一个 <datalist>。桌面浏览器和 iOS
    Safari 都认这个写法，安卓的 Chrome / Edge / 三星浏览器从来没实现过 ——
    在手机上它等于一个普普通通的文字框，点一下只弹键盘，候选一个都不出来。

    现在换成跟「和饭的关系」一样的写法：框底下排一排按钮
    「片 / 粒 / 袋 / mg / ml / 滴 / 喷 / 单位」，点哪个就把哪个填进框里，
    选中的那个按钮会亮起来。右边那个框没动，还是可以自己手打。

    自己新增的日程类型，只要勾了「剂量（数量 + 单位）」这一栏，也是一样的按钮，
    不用另外设置。

  · 离线缓存版本从 v12 升到 v13  ——  sw.js


--------------------------------------------------------------------------------
【升级须知】
--------------------------------------------------------------------------------
  1. 以前记的日程一条都没动，单位填的还是原来那个字。只是以后新填的时候，
     可以用按钮点了。
  2. 「每次剂量」那两格里，左边还是数字、右边还是单位，位置没变。
  3. 电脑上看起来会多出一排按钮，以前那种「点框弹候选」的方式没有了 —— 两边统一。


--------------------------------------------------------------------------------
【怎么验证】
--------------------------------------------------------------------------------
  1. 手机上打开「日历及健康」→ 右下角加号 → 选「服药」→ 找到「每次剂量」。
     那个框下面应该有一排按钮：片 粒 袋 mg ml 滴 喷 单位。
     点「片」，右边框里立刻出现「片」，按钮亮起来。往框里手打「半片」也行。
  2. 把「1」和「片」填好、起个药名、选个时间，保存，看那天的日程上是不是
     「1片」。
  3. 自动自检（可选，装了 Node 就行）：

         node scripts/smoke.mjs

     浏览器开 http://localhost:5173/scripts/flowcheck.html 和
     http://localhost:5173/scripts/modcheck.html ，
     右边那栏最后一行应该都是 DONE，并且一个 FAIL 都没有。

  v0.5.4   2026-10-11    设置上不再冒小橘红点；吃药到点弹卡确认；今日页能一天天翻；搜索能打日期
================================================================================
【一句话】
  这一版办了四件事。一，设置按钮上那个小橘红点去掉了 —— 它本来是「该导出了」
  的意思，可算法让没怎么用过的人也看到它亮，改成真到 21 天没导出时，在主页
  最上面出现一行「需要保存记录」。二，吃药到点会弹一张「是否吃药」的卡，把这一档
  该吃的药挨个列出来，每条右边一个「是」，底下还有「全部服用了」；记下的时间会
  显示在日程右边，过了点还没记的写「服药缺漏」，记错了、忘了记都能改。三，「今日」
  那一页也能像「状态记录」那样一天天左右翻。四，搜索框里可以直接打日期，把某一天
  的安排全调出来。


--------------------------------------------------------------------------------
【改动】
--------------------------------------------------------------------------------
  · 设置按钮上的小橘红点整个去掉  ——  assets/app.css、assets/js/app.js

    .corner-btn.is-due::after 那条 9×9 的小圆点样式删掉了。以前它是「距离上次
    导出满 14 天」就亮，而天数是从「最早的一条记录」算起的 —— 刚上手、还没
    怎么用过的人也会看到它亮，看着像出了什么事。现在不碰图标，改成在主页最上面
    写一行字。

  · 「该导出了」的提醒改成主页顶上一行字，门槛从 14 天放宽到 21 天
      ——  index.html、assets/app.css、assets/js/export.js

    主页加了一个 <p id="homeNotice">，写着「需要保存记录」；平时是藏着的，
    真到 21 天没导出才露出来。它只是一行字，点它不做事（要导出还是走设置里那行）。
    设置面板里「该导出一份了」那行原样留着，没动。

  · 吃药到点弹「是否吃药」的卡  ——  assets/js/modules/calendar.js

    到点了会弹一张卡，把这一档该吃的药一条条列出来，每条右边一个「是」按钮；
    底下是「等一会儿」和「全部服用了」。点「是」记下此刻的时间，卡里剩下的接着问；
    点「全部服用了」就一次全记完。这张卡跟着「日历 · 到点提醒」那个开关走，
    开关关着的时候不会弹。

  · 日程右边显示吃药时间，没吃的写「服药缺漏」  ——  同上、assets/app.css

    服药这一类的日程，列表右边会多一小块：记过的写「已服 HH:MM」（橘色），
    过了点还没记的写「服药缺漏」（红字），还没到点的就空着。再右边还有一个
    「记」或「改」的小按钮。

  · 吃药时间能改、也能补记  ——  同上

    点「记」或「改」弹出「记录服药」：上面写清是哪种药、原定几点，下面一个时间框
    可以随便选（早于或晚于原定都行），旁边一个「就是现在」一键填成当下。
    吃的当时忘了记，事后补上走的就是这里。

  · 「今日」页能一天天左右翻  ——  同上

    顶上左右各一个箭头，一天一天翻，往后翻也行。翻到别处会多出一个「今天」小
    按钮，点一下跳回来。月历和今日页共用「选中的是哪天」，所以两边是同步的。

  · 搜索框能直接打日期  ——  同上

    框里打 2026-10-11、2026/10/11、2026年10月11日、10月11日、10-11 都认，
    把那天排的日程全列出来，点一条就跳到那天。过去的日子、往后的日子都行。
    不写成日期的词，照旧按药名、医院、备注搜。

  · 设置里「到点提醒」的说明补一句  ——  同上

    那段小字加上了「服药到点会弹一张『是否吃药』的卡」。

      就医、复诊、体检 —— 各自的栏（医院、科室、医生、备注之类）

    两种图共用同一套网格、纵轴刻度和日期轴，只在「画什么形状」这一步分岔：

        写指标 → buildFrame()  把格子、网格、日期轴先铺好，返回 yOf / xOf 两个换算函数

                          ├─ 没写 style → drawLine()  折线：横轴首尾贴边，

                                                       没记录的日子直接空着

    柱子长得窄，手指点不准。所以每根柱子下面垫了一块透明的「命中区」，
    占满自己那一整格，点击和悬停都交给它 —— 柱子自己设 pointer-events="none" 让开。

  · 柱子长什么样  ——  assets/js/charts.js
    每根柱子占自己那一格的 62%（最宽 20），剩下的就是两根之间的空隙。

  v0.2    2026-09-28    框架改造：把「模块」做成真正的 mod
================================================================================

【一句话】
  以前「加一个模块」要同时改 4 个文件，而且外部模块的 markdown 永远导不出来；
  现在新建一个 .js 文件、在设置里导入就行。
  AI 助手也变成了一个模块——关掉它，设置里的 AI 分区和日记里的两个按钮一起消失。


--------------------------------------------------------------------------------
【新增功能 · 模块系统】
--------------------------------------------------------------------------------
  · 设置页最上面多了一个「模块」分组。内置模块和自己导入的模块在同一个列表里，
    没有特权通道。
  · 导入模块——选本地 .js 文件，先弹确认框列出它自称的 id 与名字，再决定装不装。
  · 导出模块——任何模块都能导出源码（内置的也行）。想改内置模块，
    导出来改完再导回去就是你的了。
  · 禁用 / 启用——关掉就不显示，数据仍留在本机；再打开就回来。
  · 卸载——删掉模块代码。会问一句要不要连它记录的数据一起删，默认不删。
  · 更新——同一个 id 再导入一次就是更新，不会变成两份。
  · 「停用全部自定义模块」按钮，装了个不听话的模块时的自救开关。
  · 坏模块隔离（四条防线）：
      ① 求值失败 → 设置里多一条「加载失败」条目，写明原因、一键删掉，其余照常
      ② 渲染失败 → 那一栏换成一张错误卡片，不影响别的模块
      ③ 导出失败 → 只有这一段变成「导出时出错」，整份 md 仍然导得出来
      ④ 启动顺序上外壳先渲染、模块求值推迟到首屏之后，保证设置页一定打得开
  · 逃生舱 ?nomods=1——模块里有死循环卡死页面时，在地址后面加上它就能跳过
    全部自制模块先启动，进去把那条删掉。

--------------------------------------------------------------------------------
【新增功能 · 声明式字段】
--------------------------------------------------------------------------------
  模块只声明 fields，核心自动推导出：表单控件 / 收起时的摘要 / md 导出 / 波状图指标。
  6 种控件覆盖原来全部需求：

      scale     评分格 1–10，再点一次取消
      slider    滑动条
      number    数字框（可配快捷按钮）
      enum      二选一按钮组
      text      单行输入框
      textarea  多行输入框（可挂工具按钮）

  例：这样一个 11 行的体重模块，「记录页多一栏 + md 里多一段 + 波状图多一条曲线」
  全部自动接上，一行别的代码都不用改：

      ellipse.define({
          apiVersion: 1, id: 'weight', name: '体重', icon: 'chart',
          fields: [{ key: 'kg', type: 'number', label: '体重', unit: 'kg', step: 0.1 }]
      });

--------------------------------------------------------------------------------
【AI 助手变成一个模块】
--------------------------------------------------------------------------------
  · 设置里的 AI 分区整段从 app.js 搬进了 assets/js/modules/assistant.js。
  · 日记里的「语音转写 / 整理成日记」两个按钮，改成查一次工具注册表——
    工具不存在就不渲染，不再写死。
  · 所以：关掉「AI 助手」模块 → AI 分区和那两个按钮一起消失。
    这就是 mod 该有的行为。

--------------------------------------------------------------------------------
【内部改动】（界面和功能没变，但「以后好不好改」差很多）
--------------------------------------------------------------------------------
  修掉了 6 处结构性硬编码：

   1. export.js 里 if (id==='mood') … else if ('sleep') … 的逐模块写死
      → 改成通用推导。这条最致命：不修的话外部模块永远导不出 markdown。
   2. storage.js 反过来 import 界面层的模块表 → 删掉。
      依赖方向变成单向：registry → storage，storage 不认识 registry。
   3. 表单控件本来是私有函数，外部模块拿不到 → 收进 core/fields.js，
      通过 ellipse.ui 公开。
   4. 存值靠 CSS 类名「嗅探」（.chip / .num-input …）→ 改看控件的 data-type 属性，
      外部模块自己写的控件也存得进去。
   5. AI 配置的 HTML 写死在 app.js 的模板字符串里 → 搬进模块文件。
   6. 「状态波动图」在 4 个地方被特判 → 变成普通的 panel 型模块。

  目录分层：
      assets/js/core/     引擎。不认识「情绪」「睡眠」「AI」，只认识模块契约。
      assets/js/modules/  内容。内置模块拆成 7 个文件（原来塞在 modules.js 里），
                          这样「导出内置模块 → 改 → 装回去」这条路才是真的通的。

  说明：app.js 从 1150 行变成 1214 行，没有变短。因为它接手了设置页的模块管理
  与导入 / 导出 / 卸载界面，但职责干净了——模块定义、AI 配置、逐模块的 md 全搬走了。
