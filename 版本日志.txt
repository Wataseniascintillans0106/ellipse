  v0.2.11   2026-10-08    返回按钮搬进页头顶栏，挪到左边
================================================================================
【一句话】
  「状态记录」页和模块页（比如「状态波动图」）原来的返回按钮，是浮在右上角的
  一枚大白圆钮。现在它搬进了页头最上面那条栏，站在标题左边 ——
  就是手机上返回键的位置。点起来更顺手，也不再挡住右边的内容。


--------------------------------------------------------------------------------
【改动】
--------------------------------------------------------------------------------
  · 返回按钮搬进顶栏左边  ——  index.html + assets/app.js + assets/app.css

    页头多了一条顶栏（.head-row）：左边是返回箭头，右边是标题（「状态记录」/
    模块名），两者同一行。原来是 56px 的白色圆钮浮在右上角，现在是页头里
    44px 的一个干净箭头，只有悬停 / 按下才浮一层浅色。

    返回按钮全局仍然只有一个（id 还是 backHomeBtn），哪一页露着脸就由
    app.js 的 placeBackBtn() 把它挪进那一页的顶栏 —— 不重建节点，
    所以挂上的事件和收放状态都跟着它走。

  · 收起时留位置，标题不跳  ——  assets/app.css

    导出面板打开时返回按钮要收起。它现在顶栏里站第一格，一撤走整行的标题
    就会「跳」到最左边（实测确实会）。所以收起时改成「看不见但仍占着位置」
    （visibility: hidden），标题就稳稳待在原处。

  · 顶栏高度与左边距  ——  assets/app.css

    顶栏 44px 高（手指点得到），整体往左探出正文的边距，让箭头贴着屏幕边；
    正文（区间按钮、曲线）仍从 --main-pad 那条线开始，一个字没挪。

  · 自检页跟着更新  ——  scripts/flowcheck.html

    原来的断言「曲线块与标题左右对齐」是照着旧版设计的（标题也在正文那条线上）。
    标题搬进顶栏后它必然不再站在那条线上，于是改成两条更贴切的：
      · 曲线块与区间按钮左右对齐（正文仍是一条左边线）
      · 返回按钮在标题左边、同一行，而且是页头里的按钮（不是浮着的圆角标）
    记录页和模块页各测一遍。


--------------------------------------------------------------------------------
【升级须知】
--------------------------------------------------------------------------------
  · sw.js 的缓存版本号不动（只改了已有文件的内容，没有新增文件）。
    装过 PWA 的话，重开一次页面就能拿到新版；想立刻生效就 Ctrl + F5 强刷一次。
  · 不碰任何数据：记录、导出的 md、模块开关与顺序全都照旧。
  · 只影响「状态记录」页和模块页的页头。主页（没有返回键）、设置面板
    （右上角那个是「关闭」不是「返回」）都没动。


--------------------------------------------------------------------------------
【怎么验证】
--------------------------------------------------------------------------------
  node scripts/smoke.mjs                         全部通过
  scripts/flowcheck.html                         全部 ok，DONE（无 FAIL）
  scripts/modcheck.html                          全部 ok，DONE

  自己看一眼：
      双击「启动预览.bat」→ 主页右侧竖栏点「状态记录」。
      1. 返回箭头应当在页头最上面、标题「状态记录」的左边（原来它在右上角）。
      2. 点它回主页；再从竖栏点进「状态波动图」，那边的顶栏也是同样的样子。
      3. 在记录页点底部的「导出今天的记录」打开面板 → 顶栏里的箭头消失，
         但标题「状态记录」**不会**跟着挪位。关掉面板，箭头回来。

  v0.2.10   2026-10-08    设置里的模块分成两栏，栏能展开收起
================================================================================
【一句话】
  设置页的模块清单原来是一长条，现在分成两栏：「数值图」住着「状态波动图」，
  「状态记录」住着记录页上的那些卡片。两栏的标题条都能点，点一下收起来、
  再点一下展开（收着还是开着会记住，下次打开设置还是那样）。
  关掉的模块还会自己沉到同栏的最下面，一眼就知道手上留着哪几条。


--------------------------------------------------------------------------------
【改动】
--------------------------------------------------------------------------------
  · 两栏：数值图 / 状态记录  ——  assets/js/app.js

    「数值图」= 页面型模块（kind: page），现在就是「状态波动图」，各占主页竖栏一个入口。
    「状态记录」= 记录型 + 面板型（registry.isCard），就是记录页上的那些卡片。
    以后再有页面型模块，也会自己落进「数值图」栏，不用改代码。

  · 栏能展开 / 收起  ——  assets/js/app.js + assets/app.css + assets/js/storage.js

    标题条整个是一条按钮，左边一个小箭头：朝下=开着，朝右=收着。
    状态存在设置里（settings.ui.groups），和开关、顺序一样跟着本机保存；
    默认是展开的 —— 收起来是给人主动用的，不是给人添麻烦的。
    样式沿用原来的 .set-group，只是多了 .set-group--fold 这一个花样，
    「显示」「数据」「安装」这些栏没动，还是老样子。

  · 关掉的沉到栏底 + 箭头按块算边界  ——  assets/js/app.js

    「开着的前面、关掉的后面」这条规矩本来就有（原来在 registry.manageList 里），
    这次搬进设置页，按栏各算一份。同时修了一个跟着来的小毛病：
    沉到栏底的模块，它的上移箭头原来是亮的，可按下去什么也不会发生
    （因为上面全是还开着的模块，顺序换了也看不出动静）。
    现在箭头的边界按「开启块」「关闭块」分别算，点了没用的箭头直接灰掉。

  · 删掉 registry.manageList()  ——  assets/js/core/registry.js

    它的活已经搬进设置页，而且没有任何地方再用它了（模块也拿不到它）。
    一条规矩只留一处，免得以后两边改岔了。


--------------------------------------------------------------------------------
【升级须知】
--------------------------------------------------------------------------------
  · sw.js 的缓存版本号不动（只改了已有文件的内容，没有新增文件）。
    装过 PWA 的话，重开一次页面就能拿到新版；想立刻生效就 Ctrl + F5 强刷一次。
  · 不碰任何数据：记录、导出的 md、模块开关与顺序全都照旧。
  · 设置里多了一个 ui.groups 字段，只用来记两栏收没收起来；
    老设置文件没有它也一样能用（当作全展开）。导出备份、导入备份都不受影响。
  · 「AI 助手」没参与分栏，照旧单独一行跟在两栏后面（它是个弹出面板，不产记录）。


--------------------------------------------------------------------------------
【怎么验证】
--------------------------------------------------------------------------------
  node scripts/smoke.mjs                         全部通过
  scripts/flowcheck.html                         全部 ok，DONE（无 FAIL）
  scripts/modcheck.html                          全部 ok，DONE

  自己看一眼：
      双击「启动预览.bat」→ 主页右下角齿轮 → 设置。
      1. 模块清单里应当看到两条带小箭头的标题：「数值图」和「状态记录」。
      2. 点「状态记录」那一条 → 整栏收起，箭头从朝下转成朝右；关掉设置再打开，

  v0.2.9    2026-10-08    设置里的模块开关：一眼能看出开没开
================================================================================
【一句话】
  设置里的模块开关原来是光秃秃一枚灰色胶囊，关掉之后只是滑块滑到左边——
  名字和说明一个字不变，扫一眼分不出哪个关了。现在关掉的模块整行变淡，
  开关上直接写「开 / 关」两个字，名字后面还挂一枚「已关闭」小签，三个提示叠在一起。


--------------------------------------------------------------------------------
【改动】
--------------------------------------------------------------------------------
  · 关掉的模块整行变淡  ——  assets/js/app.js + assets/app.css

    模块行多了一个 is-off 类，图标、标题、说明一起降到 45% 不透明度。

  v0.2.7    2026-10-08    「状态波动图」搬去主页，成了一整页
================================================================================
【一句话】
  原来「状态波动图」是记录页最下面的最后一张卡片。现在它从记录页搬走了 ——
  主页右侧竖栏里多了一个图标按钮，就压在「状态记录」的正上方，大小、样子都和它一样。
  点它进的是一整页：标题在左上角，下面一排 7 天 / 1 个月 / 3 个月的按钮，
  内容比一屏高，整页可以上下滑，右上角有返回箭头，最下面还有一行小字。
  设置里那个「状态波动图」开关还在 —— 关掉它，主页这个按钮就跟着没了（记录页不受影响）。


--------------------------------------------------------------------------------
【改动】
--------------------------------------------------------------------------------
  · 模块契约多了第四种类型：page（独立页面型）  ——  assets/js/core/validate.js
                                                    assets/js/core/registry.js
                                                    assets/js/core/api.js

    前三种是 record（收字段的卡片）、panel（在记录页上画一整块）、service（不占位置的服务）。
    page 是第四种：不占记录页的位置，自己在主页竖栏上占一个入口，点开是一整页。
    它和 panel 一样必须有 mount(body, ctx)，校验器会拦下没写 mount 的。

    新加的查询叫 pageModules()：按顺序给出「已启用的页面型模块」都有谁，竖栏照着它画。
    isCard 是张白名单、manageList 会把非卡片排在最后、排序按钮也自动不画 ——
    所以新类型天然不会跑进记录页，这三件事一行都不用另写。

  · 「状态波动图」改型  ——  assets/js/modules/trend.js
    kind 从 panel 改成 page，去掉 defaultOpen（独立页面没有展开/收起这回事），
    多了一行 note（就是页面最下面那行小字）。mount 和它画的图一个字没动。

  · 外壳认识「一整页」这种页面  ——  index.html、assets/js/app.js
    index.html 里多了一层通用的容器 #viewPage：标题取模块的 name、内容由模块的 mount 画、
    底注取模块的 note。以后再加一个页面型模块，这里一个字都不用改。
    app.js 里 state.page 现在可以是 'home' / 'record' / 某个页面型模块的 id；
    竖栏改成「先遍历页面型模块、再把「状态记录」钉在最下面」。

  · 页面上的曲线块和原来长得一模一样  ——  assets/app.css
    图表那一整套样式（曲线、区间按钮、小字）本来就是通用规则，只有 4 条挂在
    .module[data-kind="panel"] 底下；把这 4 条的选择器扩成「面板卡片和整页都管」即可。

  · 顺带修好一个老 bug：index.html#record 一直进不去记录页
    原因是一句 history.replaceState(…, '#home') 写在了「读地址栏」之前，
    等后面去读的时候地址早被冲成 #home 了。改成先读、再规范化，这个深链接就通了。

  · 三个自检文件跟着改  ——  scripts/smoke.mjs、scripts/flowcheck.html、scripts/modcheck.html
    波状图的断言从「记录页最后一张卡片」整批搬到「主页竖栏 + 这一页」上重写。
    原来的「设置里关掉 → 卡片消失」改成「设置里关掉 → 竖栏按钮消失」。


--------------------------------------------------------------------------------
【升级须知】
--------------------------------------------------------------------------------
  · sw.js 的缓存版本号不动：全程只改已有的文件，没有新增文件（SHELL 清单里本来就列着
    trend.js）。装过 PWA 的话，重开一次页面就能拿到新版；想立刻生效就 Ctrl + F5 强刷。
  · 记录页会少一张卡片：最下面变成「日记」。你记的记录一条都没动，导出 md 也不受影响
    （状态波动图本来就不进导出）。
  · 这一页的地址是 index.html#page/trend。写成 #page/ 开头是故意的 ——
    模块自己的 id 有可能是 record 或 home，直接拼上去会和主页、记录页撞名。
  · 设置里存着的旧记录里，「状态波动图是展开的」那一条从此没人读了，留着没副作用，不清它。
  · 想自己看一眼：双击「启动预览.bat」→ 主页右侧竖栏应当有两个图标。


--------------------------------------------------------------------------------
【怎么验证】
--------------------------------------------------------------------------------
  node scripts/smoke.mjs                         全部通过
      （多了 4 条：波状图是页面型模块 / 页面型模块要 mount / 它不占记录页的卡片位 /
        它是主页竖栏里的一个入口）

  下面这些要等页面真的画出来才看得到，所以在浏览器自检页里：

      浏览器打开 http://localhost:5173/scripts/flowcheck.html

  里面新增/改写的主要是：

      · 记录页最后一张是日记、里面没有波状图卡片

      · 「框架与记录页一致」是量出来的，不是看着像：这一页的标题左边缘、顶边
        与记录页标题对在同一个像素上；区间按钮在标题下面、小字在所有图的下面、
        曲线块与标题左右对齐

        number 字段上的 max 是「输入上限」，不是「纵轴上限」；

  · 卸载——删掉模块代码。会问一句要不要连它记录的数据一起删，默认不删。
  · 更新——同一个 id 再导入一次就是更新，不会变成两份。
  · 「停用全部自定义模块」按钮，装了个不听话的模块时的自救开关。
  · 坏模块隔离（四条防线）：
      ① 求值失败 → 设置里多一条「加载失败」条目，写明原因、一键删掉，其余照常
      ② 渲染失败 → 那一栏换成一张错误卡片，不影响别的模块
      ③ 导出失败 → 只有这一段变成「导出时出错」，整份 md 仍然导得出来
      ④ 启动顺序上外壳先渲染、模块求值推迟到首屏之后，保证设置页一定打得开
  · 逃生舱 ?nomods=1——模块里有死循环卡死页面时，在地址后面加上它就能跳过
    全部自制模块先启动，进去把那条删掉。

【新增功能 · 声明式字段】
--------------------------------------------------------------------------------
  模块只声明 fields，核心自动推导出：表单控件 / 收起时的摘要 / md 导出 / 波状图指标。
  6 种控件覆盖原来全部需求：

      scale     评分格 1–10，再点一次取消
      slider    滑动条
      number    数字框（可配快捷按钮）
      enum      二选一按钮组
      text      单行输入框
      textarea  多行输入框（可挂工具按钮）

  例：这样一个 11 行的体重模块，「记录页多一栏 + md 里多一段 + 波状图多一条曲线」
  全部自动接上，一行别的代码都不用改：

      ellipse.define({
          apiVersion: 1, id: 'weight', name: '体重', icon: 'chart',
          fields: [{ key: 'kg', type: 'number', label: '体重', unit: 'kg', step: 0.1 }]
      });

  修掉了 6 处结构性硬编码：

   2. storage.js 反过来 import 界面层的模块表 → 删掉。
      依赖方向变成单向：registry → storage，storage 不认识 registry。
   3. 表单控件本来是私有函数，外部模块拿不到 → 收进 core/fields.js，
      通过 ellipse.ui 公开。
   4. 存值靠 CSS 类名「嗅探」（.chip / .num-input …）→ 改看控件的 data-type 属性，
      外部模块自己写的控件也存得进去。
   5. AI 配置的 HTML 写死在 app.js 的模板字符串里 → 搬进模块文件。
   6. 「状态波动图」在 4 个地方被特判 → 变成普通的 panel 型模块。

      assets/js/core/     引擎。不认识「情绪」「睡眠」「AI」，只认识模块契约。
      assets/js/modules/  内容。内置模块拆成 7 个文件（原来塞在 modules.js 里），
                          这样「导出内置模块 → 改 → 装回去」这条路才是真的通的。
