# PWA 部署与安装小抄

给未来的自己看的。忘了怎么把 ellipse 装到手机上就翻这里。

---

## 一、这是干嘛的，我为什么要折腾

**PWA** 就是"把这个网页装成手机上的一个 App"。装完的好处：

| 好处 | 说人话 |
| --- | --- |
| 全屏打开 | 没有浏览器地址栏，看着就是个 App |
| 主屏图标 | 和别的 App 摆在一起，不用每次翻浏览器书签 |
| **断网也能用** | 页面和代码缓存在本机，飞机上、信号差的地方都能记 |
| **能装到主屏** | ⚠️ 这条最关键，见下 |

### ⚠️ 为什么手机连 Wi-Fi「只能看版式」

浏览器有个安全规矩：**离线缓存、安装到主屏这类能力，只授权给"安全来源"**。

安全来源只有两种：

1. `https://` 开头的网址
2. `http://localhost`（只有电脑自己访问自己才算）

所以你现在用 `启动预览.bat`（或 `node scripts/serve.mjs`）起服务器、
手机连同一个 Wi-Fi 访问 `http://192.168.1.x:5173` ——
**这个地址不算安全来源**，手机上 Service Worker 不起来、也弹不出「安装应用」。
这不是 bug，是浏览器的规矩。

**只有部署到 HTTPS，手机上才能真的装成 App、才能断网可用。**

## 二、部署到 GitHub Pages（免费，推荐）

### 前提：仓库得是公开的

免费账号的 GitHub Pages **只能用于公开仓库**。

- 仓库已经是公开的 → 直接往下走
- 仓库是私人的 → 二选一：
  - 改成公开：仓库页 → **Settings** → 拉到底 **Danger Zone** → **Change visibility**
    （改公开后**之前所有提交历史一起公开**，但你**不用担心私人记录泄露**，理由见第八节）
  - 或者换个托管，见下面「不想公开怎么办」

### ⚠️ 先记住这个坑

> 设置 Pages 时，**分支目录一定选 `/(root)`，千万别选 `/docs`**。
>
> 因为本项目恰好有个 `docs/` 文件夹（放的就是这篇文档），而 GitHub Pages 的下拉框里
> `/docs` 是个真实选项。选错的话，GitHub 会拿 `docs/` 当网站根目录，
> 而 `index.html` 其实在根目录 —— 你会得到一个 **404 的空站**，还很难看出为什么。

### 详细步骤

**1. 把项目推上 GitHub**

照 [版本管理.md](版本管理.md) 的做法，在 GitHub Desktop 里 Commit → **Push origin**。

**2. 进仓库的 Pages 设置**

浏览器打开你的仓库页 → 顶部 **Settings**（不是个人设置，是仓库的）→
左侧栏往下找 **Pages**。

**3. 配置来源**

在 **Build and deployment** 下面：

| 选项 | 选什么 |
| --- | --- |
| Source | **Deploy from a branch** |
| Branch | **main** |
| 分支右边的目录框 | **`/(root)`** ← 就是这里别选错 |

点 **Save**。

**4. 等几分钟，拿到网址**

回到 **Pages** 页面，顶部会出现一行绿底的提示，网址长这样：

```
https://你的用户名.github.io/ellipse/
```

刚点完 Save 要等 1～3 分钟，页面刷新几次才出。**这个网址就是你的 App 地址。**

**5. 打开验一下**

用手机浏览器打开这个 `https://` 网址，应该看到 ellipse 主页。

> 💡 网址末尾带不带 `index.html` 都行，`https://你的用户名.github.io/ellipse/` 和
> 加 `/index.html` 是同一个页面。

### 不想公开怎么办

这几家都免费、都自带 HTTPS、**都支持私人仓库**，做法和 GitHub Pages 差不多
（连上仓库 → 选分支 → 自动部署）：

- Cloudflare Pages
- Netlify
- Vercel

原理一样：**只要最后给你一个 `https://` 的网址就行**，剩下第四节照做。

## 三、装到手机上

### 安卓（Chrome / Edge）

**方法一（有提示时）**：打开网址，Chrome 可能在底部弹一条「把 ellipse 添加到主屏幕」，点它。

**方法二（手动）**：

1. 打开网址
2. 点右上角 **⋮** 菜单
3. 选 **「安装应用」**（有的版本写「添加到主屏幕」）
4. 确认

### iPhone / iPad（Safari）

**必须用 Safari**，Chrome 在 iOS 上装不了。

1. 用 Safari 打开网址
2. 点底部中间的 **分享** 按钮（方框里一个向上箭头）
3. 在菜单里往下翻，选 **「添加到主屏幕」**
4. 右上角点 **「添加」**

> iOS 只认 Safari 的「添加到主屏幕」，而且**没有**安卓那种「安装应用」的弹窗，
> 找不到按钮是正常的，按上面三步手动加。

### 应用里也有这份说明

主页 → 右下角**设置** → 最下面 **「安装到主屏」**：

- 能装的时候，那块里有个 **「安装到主屏」** 按钮，点一下直接调起系统的安装确认
- 不能装的时候按钮是灰的，下面一行小字会告诉你**当前该用哪种方式装**
- 已经装好了，右上角会显示「已装到主屏」

## 五、改了代码怎么更新

### 平常改代码：什么都不用做

Push 到 GitHub → 等一两分钟 → **重新打开 App**（或下拉刷新）就是新版。

**缓存策略是"联网优先"**：每次打开都先去网上要最新的，网络不好才用本机副本
（超过 3.5 秒没回来就先用旧的把页面起起来，后台继续下载新版）。
所以你**不会**遇到"改了代码手机上还是旧的"这种卡住的情况。

### ⚠️ 改了 `sw.js`、或新增 / 删除了文件：必须把版本号 +1

这是**最容易忘的一步**，单独拎出来说。

打开 [sw.js](../sw.js)，第一行常量：

```js
const CACHE = 'ellipse-cache-v5';   // 当前是这个
```

**只要你动过 `sw.js` 的内容、或者新增 / 删除了文件，就把版本号 +1
（现在是 `v5`，下次改 `v6`）。**

**为什么**：Service Worker 在 `activate` 时会删掉"所有不是当前版本号"的旧缓存。
版本号不变，它就会认为新旧是同一份缓存，**旧文件永远清不掉**，
你会看到改了跟没改一样。而新增的文件没被预缓存、删掉的文件还留在旧缓存里，
也是同一个道理。

> 判断方法：**只改 `index.html`、`assets/`、`fonts/` 里*已有*文件的内容 → 不用动版本号。
> 改了 `sw.js` 本身、或者增删了文件（记得同时改 `sw.js` 的 `SHELL` 清单）→ 一定要动。**

### 换了图标

替换根目录的 `icon-192.png` 和 `icon-512.png` 两个文件就行。

换完手机上可能要**先删掉主屏那个旧图标，再重新装一次**，图标才会更新 ——
主屏图标是安装那一刻存下来的，不会自己跟着变。

## 六、出问题了怎么查

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 菜单里**没有**「安装应用」 | 三个条件缺一个：① 不是 HTTPS ② `sw.js` 和 `index.html` 不在同一目录 ③ `manifest.webmanifest` 读不到 | 先确认网址是 `https://`；再确认两个文件都在根目录；然后在电脑 Chrome 的 DevTools → **Application → Manifest** 看报什么错 |
| 手机连 Wi-Fi 预览时，什么都装不了 | 局域网 HTTP 不是安全来源 | 这是**正常的**。局域网预览只能看版式，要试安装 / 离线就部署到 HTTPS |
| 改了代码，打开还是旧的 | 一般是没 Push，或者刚 Push 还没部署完 | 确认 GitHub Desktop 里 Push 过了；GitHub Pages 每次部署要一两分钟；再不行看是不是改了 `sw.js` 没升版本号 |
| 出现一页「**暂时打不开**」 | 断网了，且本机还没有离线副本 | 这是**故意做的离线页**，不是坏了。连上网点「重试」。第一次打开前必须有网，才有离线副本 |
| 双击 `index.html` 一片空白，写着「页面没有正常启动」 | `file://` 下 Chrome / Edge / Firefox **都会拦掉 ES module**（只有 Safari 宽松）。这跟安全来源是两回事，是**根本打不开** | 用 `启动预览.bat` 起服务器，或部署到 HTTPS。也就是本页第一节说的：**这条路是死的** |
| 手机上装的图标是旧图 | 主屏图标在安装那一刻定格 | 删掉主屏图标重新装一次 |

### 想确认离线缓存到底有没有在工作

电脑 Chrome 打开 `http://localhost:5173/index.html`（**localhost 也算安全来源**，
所以本地就能测），然后：

1. F12 打开 DevTools
2. **Application → Service Workers** —— 应该看到 `sw.js`，状态是 **activated**
3. 在同一页勾上 **Offline**，刷新 —— 页面应该**照常打开**

> 注意：测这个必须用 `http://localhost:5173`，不能双击 `file://` 打开。

## 七、跟 AI 接口有关的一点

[sw.js](../sw.js) 里有一句很关键的话：

```js
if (url.origin !== self.location.origin) return;
```

意思是：**只接管本站自己的请求，别人的一律放行。**

所以发往 `api.deepseek.com`、`api.openai.com` 的请求**原样直通、绝不缓存**。
这是特意写的 —— 如果连 AI 接口的返回也缓存，你会拿到上一次的旧回答，还很难查。

## 八、常见疑问

**Q：部署到公开仓库，我的记录会泄露吗？**
A：不会。记录只在浏览器 localStorage 里，**从来就不是项目文件**。
项目里唯一跟"数据"有关的 [scripts/seed.html](../scripts/seed.html) 写的是正弦函数生成的**假数据**。
API Key 同理，只在你本机的浏览器里。这条在 [版本管理.md](版本管理.md) 里也说过。

**Q：免费吗？**
A：GitHub Pages 对公开仓库免费，Cloudflare Pages / Netlify / Vercel 免费额度也够个人用。
只是**别把大文件堆进去**（本项目的字体文件 1.1MB，没问题）。

**Q：装到主屏的 App 和电脑上记的数据是同一份吗？**
A：**不是。** 这跟装不装 App 无关 —— 数据永远只认"同一台设备的同一个浏览器"。
手机记的和电脑记的是两套，迁移只能靠设置里的 **备份 JSON** 手动导入导出。

**Q：装完以后，原来的网址还能用吗？**
A：能。装到主屏只是多了一个入口，网址照常访问，两边看到的是**同一份数据**。

**Q：我想换域名 / 换个托管，代码要改什么吗？**
A：代码不用改。所有路径都是相对写法（`./manifest.webmanifest`、`assets/app.css`），
放在任何子目录下都能用。

**⚠️ 但要记住：换网址 = 换一份数据。** 浏览器把 localStorage 按"网址"隔离，
`http://localhost:5173`、`https://a.github.io/ellipse/`、`https://b.netlify.app/`
看到的是**三份互不相通的数据**。换过去之后旧网址里的记录不会跟过来，
只能靠设置 → 数据里的 **备份 JSON** 手动搬：旧网址导出 → 新网址导入。

（"装到主屏"不算换网址：那是同一个网址的另一个入口，数据是同一份。）

**Q：以后能不能做成 APK，直接装？**
A：目前没有 APK。而且先别急着做——**装到主屏的 PWA 和 APK 的体验差别，
主要就是"能不能上应用商店"**，但更新方式差很多：PWA 是 `git push` 一下、
所有人下次打开就是新版；APK 得重新打包、重新安装。

真要做的三条路（包壳 TWA / 用 Capacitor 整个打进去 / 继续用 PWA）写在
[README 第一节](../README.md#一怎么打开它)的「以后想做成 APK？」。

## 九、这个项目的文件清单

改动 PWA 相关的就这几个，忘了哪个是干嘛的看这里：

| 文件 | 干嘛的 |
| --- | --- |
| [manifest.webmanifest](../manifest.webmanifest) | 应用的"身份证"：叫什么名、什么图标、怎么打开 |
| [sw.js](../sw.js) | Service Worker：离线缓存 + 联网优先策略。**改它要升版本号** |
| `icon-192.png` | 图标（安卓、电脑） |
| `icon-512.png` | 图标（高清，安装时用） |
| [index.html](../index.html) | `<head>` 里的那几行 meta 是给 iOS / 安卓认的 |
| [assets/js/app.js](../assets/js/app.js) | 末尾「PWA」那一段：注册 Service Worker、处理安装按钮 |

### 加了新文件？记得加进预缓存清单

`sw.js` 里有个 `const SHELL = [...]`，列的是"装好后要先存到本机"的文件。

**为什么要有这份清单**：不预缓存的话，第一次打开那轮加载发生在 Service Worker 接管
**之前**，资源根本进不了缓存 —— 得等第二次打开才有离线副本，冷启动断网就只剩一页
「暂时打不开」。加上这份清单，第一次打开完就真的能离线用了。

**所以新增 js / css 文件时，把它加进 `SHELL` 里。** 忘了也不要紧，
`node scripts/smoke.mjs` 会检查清单有没有漏掉 `assets/` 下的文件，漏了会直接报错。

### 自检

`node scripts/smoke.mjs` 的 `[7] PWA 资源` 一节会检查：文件都在、manifest 能解析、
图标没写错名字、**预缓存清单没漏文件**。

## 十、术语小词典

| 词 | 中文 | 大白话 |
| --- | --- | --- |
| PWA | 渐进式网页应用 | 能被"装"成 App 的网页 |
| HTTPS | 加密的网址 | `https://` 开头。浏览器只信它，离线缓存与安装到主屏也只给它 |
| 安全来源 | Secure context | HTTPS 和 `localhost`。别的地址浏览器不给高级权限 |
| `file://` | 本地文件 | 双击 html 打开时地址栏的样子。既不是安全来源，而且本项目在它下面**根本跑不起来**（模块会被拦） |
| manifest | 应用清单 | 一个 json，告诉手机这个 App 叫什么、什么图标 |
| Service Worker | 后台服务员 | 躲在页面背后拦截网络请求、管缓存的脚本 |
| 缓存 (Cache) | 本机副本 | 把网页文件存一份在手机上，断网时拿出来用 |
| standalone | 独立窗口 | 装完后没有地址栏的那种打开方式 |
| 预缓存 / 运行时缓存 | — | 本项目**两个都用**：挂载时先把 `SHELL` 清单一整份存下来（预缓存），之后每打开一次就顺手更新一次（运行时缓存） |
